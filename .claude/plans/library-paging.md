# 收藏夹：往下滚自动加载，不用再点「再加载」

## 起因

2026-11-12 用户：「收藏夹 现在分页是划到最下面手动点击加载，你看看如何优化体验」。

现状（动手前读的代码）：

- 作品墙 `components/LibraryWorks.tsx`：一页 60 部，底下一个按钮「再加载 60 部（共 N 部）」，点一次接一页。
- 收藏夹页里的搜索结果 `components/LibraryHits.tsx`（`variant="page"`）：一页 30 条，同样一个「再加载 30 条（共 N 条）」。首页搜索顶上那块（`embedded`）只列 5 条 + 「在收藏夹里看全部」，不翻页。
- 「分享」页签一次全列出来，没有分页。
- 接口的上限：`GET /api/library/works` 一次最多 200 条，`GET /api/library/search` 一次最多 100 条（`routes/library/index.ts` 的 schema）。
- 作品墙重拉（识别中每 5 秒的轮询、「已有」补标、收藏夹有变动）是 `fetchWorks(shownRef.current)`——**拉回已经展开的那么多条，一次请求**。展开超过 200 条以后这个请求会被 schema 拒掉（400），界面上又不显示（有结果时错误不画），表现是墙不再更新。现在要点四次以上才碰得到；改成自动加载以后滚两屏就到。
- 「再加载」失败时：作品墙把错误存进了 `error`，但有结果时没有地方画它，等于没反应；搜索结果是弹一条提示。
- 搜索结果的静默重搜（查出有分享失效、打开 / 转存失败之后）只拉第一页，已经展开的几页会缩回去。

## 方案

### 一、交互

- **滚到快见底就自动接下一页**：列表底下放一个哨兵，进到视口下方 600px 以内（`hooks/use-near-viewport.ts` 那个全页共用的 IntersectionObserver）就加载；加载完哨兵还在范围内（屏幕高、一页没填满）就接着加载，直到填满或者全部拿完。页面在后台时浏览器不发通知，也就不加载。
- **加载中**：作品墙在末尾补**一行**海报骨架（和墙同一套列，真卡片来了不跳；为什么只能一行见实施记录）；搜索结果在末尾一行「正在加载后面的 N 条…」。
- **失败**：停住不再自动试，末尾一行「没加载出来：原因」+「重试」。不弹提示、不无声吞掉。
- **到底**：展开过一页以上才写一句「共 N 部，都在这儿了」；一页就装下的什么都不写。
- 浏览器没有 IntersectionObserver 的（很老的）退回原来的按钮。

### 二、数据（作品墙）

- 重拉分块：`refresh(count)` 把 `[0, count)` 按 200 一块并发 3 个拉回来拼上，一个 AbortController 管整轮。
- 下一页的偏移单独记（`nextOffset`），不拿「现在墙上有几张」当偏移：识别进行中条目会挪位置，新一页里可能有已经在墙上的，按作品键去重以后张数没涨，拿张数当偏移会原地打转。
- 识别中的轮询：展开不超过 200 条时照旧整窗重拉（认出来的一张张冒出来）；超过以后每轮只问计数（`limit: 1`，只更新筛选药丸上的数和「还有 N 个在识别」），墙不动——人已经滚到几百张以后，头上冒新卡也看不见，没必要每 5 秒重拉几百上千条。识别结束（轮询停下）时整窗重拉一次。
- 重拉和「接下一页」撞车：重拉回来时如果这期间又接了几页，把多出来的那截留着（按键去重），不让墙缩回去。
- 换筛选 / 排序：序号加一，在飞的「接下一页」回来对不上号就丢掉。

### 三、数据（搜索结果）

- 「接下一页」带序号，换了关键词以后回来的旧结果不拼到新结果后面。
- 静默重搜拉回已经展开的那么多条（100 一块，顺序拉）。

### 不做

- 不改接口、不动后端。
- 不做虚拟滚动：卡片是固定比例的图加两行字，图是懒加载的，几千张的 DOM 浏览器扛得住；真到几万张的库靠筛选、排序和搜索找，不靠一直滚。
- 不记「离开前滚到哪了」：从别的页面回来还是从头开始（原来也是）。要做得分清是后退回来还是点导航进来，另算。
- 不把筛选栏吸顶：用户只提了分页，先不往页面上加东西。（这里原来还写着不加「回到顶部」按钮；2026-11-13 用户要了，见末节。）
- 「分享」页签不分页（现在就是一次全列）。

## 测试

- 纯界面和取数顺序的改动，没有能单测的纯函数；typecheck / lint / 全量测试照跑。
- 浏览器冒烟（合成库：几百部认出来的作品 + 一批没认出的；结果见末节）：
  - 作品墙：往下滚自动接页，直到「共 N 部，都在这儿了」；换筛选 / 排序回到第一页；
  - 展开超过 200 条以后改一部作品（触发整窗重拉）：墙不缩、不报错；
  - 断开后端再滚：出「没加载出来」+ 重试，恢复后点重试接上；
  - 搜索结果：自动接页；
  - 浅色 / 暗色、窄屏。

**冒烟里发现并改掉的**

- **手机宽度下滚到底一次就把整个库拉完了**（390px：60 张 → 3 秒后 903 张）。原因是滚动锚定：骨架一开始给了 12 格，三列时是四行、比一屏还高，视口里只剩骨架，浏览器拿骨架当锚点，新卡片插在骨架前面时视口跟着骨架往下走，哨兵一直在视口里。改成任何宽度下只有一行骨架（`TAIL_SHOW` 按断点和列数对上），骨架加 `overflow-anchor: none`。改完 390px 下每次滚到底只接一页。
- **每次多接一页**（宽屏每跳一次 +120）。`useNearViewport` 的「在附近」是观察者上一帧说的，刚接完一页那一刻还没改口，effect 拿着旧值又接了一页。接页前用 `isNearViewport` 现量一次；改完每次 +60。

## 「回到顶部」按钮（2026-11-13）

**起因**：2026-11-13 用户看完自动加载的说明后回了一句「加「回到顶部」按钮」。样子和位置是我定的。

### 做成什么样

- 新组件 `components/back-to-top.tsx`；收藏夹页 `app/library/page.tsx` 在内容最后挂一个，作品墙、搜索结果、「分享」列表三种视图共用。别的页面没挂（要挂就是在页面内容最后加一行）。
- **什么时候出现**：往下滚过一屏（`scrollY > innerHeight`）出现，回到第一屏消失。淡入淡出加 8px 上移；系统设了「减少动态效果」就不做过渡。
- **样子**：一颗药丸「⤒ 回到顶部」，`rounded-full border bg-card/90 shadow-lg backdrop-blur`，和资源搜索页底部那条悬浮栏一个路数；悬停时边框和字变品牌色。带字，不用猜是什么。
- **位置**：内容列底部正中、离视口底边 24px。内容列窄于 576px（手机，或者平板宽度下侧栏展开着）时靠左。用容器查询看内容列的宽度（`@container` + `@xl:justify-center`），不看视口宽度。为什么不放右下角见下一小节。
- **不压最后一行**：外层是一条 `sticky bottom-6` 的透明条（不接鼠标，只有按钮接）。没出现时高度 0；出现时占一个按钮的高度。平时它贴在视口底边上方、浮在内容上；滚到页面最底时落回文档流，停在最后一行下面——作品墙到底是「共 N 部，都在这儿了」下面跟着这颗按钮。
- **点了以后**：离顶上 3 屏以内，整段平滑滚回去（看得见是从哪回来的）；更深的先瞬间跳到离顶一屏的地方，再平滑滚完最后一屏。「减少动态效果」时直接跳。
- 藏着的时候是 `visibility: hidden`：键盘焦点进不去，读屏也读不到；点完回到顶上它一藏，焦点自己回到 body。

### 位置是怎么定下来的（冒烟里改了两次）

1. **第一版：右下角 40px 圆钮**（`fixed right-6 bottom-6`，页面末尾垫 48px）。在搜索结果里一看不行：每行末尾的「⋯」在距右边 41–73px 的位置，圆钮在 24–64px，正好整个压住——截图里那一行的「⋯」看不见，`elementFromPoint` 在「⋯」中心拿到的是圆钮。「分享」列表每行末尾也是「⋯」。另外桌面上 toast 也从右下角出来。试过缩成 36px 贴边（right 8px），能让开「⋯」，但和行里的「打开 / 转存 / ⋯」挤成一排，像是那一行的第四个按钮。
2. **第二版：底部正中的药丸**。桌面宽度下三种视图里它底下都没有可点的东西（搜索结果每行中间是空的）。但 390px 下又不行：搜索结果每行的操作按钮折到第二行、靠右排（x 从 171 到 357），正中的药丸（142–248）压住「打开」。
3. **窄的时候靠左**（16–122）：搜索结果左边是缩略图和文字；「分享」列表左边是封面，它和标题是同一个动作（打开分享），压着一个不碍事。一开始用 `sm:` 断点切；量到 768px（侧栏展开，内容列只有 464px）时居中的药丸离「打开」只差一点，换成看内容列宽度的容器查询。算下来居中不碰按钮要求列宽 ≥ 512px，阈值取 576px（`@xl`）。

| 视口 | 内容列 | 药丸 | 间隙 |
|---|---|---|---|
| 1440（侧栏展开） | 1136 | 居中 | 没有重叠的按钮 |
| 1024（侧栏展开） | 720 | 居中 | 104px |
| 768（侧栏展开） | 464 | 靠左 | 155px |

### 平滑滚动要多久

Chrome 里量的 `window.scrollTo({ top: 0, behavior: "smooth" })`：900px 0.73 秒、1500px 0.92 秒、3000px 1.31 秒，7000px 以上封顶 1.53 秒。几十屏的海报在眼前刷一秒半没有必要，所以超过 3 屏先跳再滑：从 36000px（903 部全部展开的最底下）回顶 0.64 秒，3 屏以内的 0.7–1.1 秒。

### 浏览器冒烟（2026-11-13）

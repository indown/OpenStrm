# 追更与整理：新集沿用上次的整理结果 —— 分析与计划

> 状态：**四块都已实施、提交，2026-10-14 115 / 夸克真机验过**（真机发现的问题已修）；评审、推送、发版等用户定。最后更新：2026-10-14

## 起因

用户问：追更之后整理改了名，追更会不会出问题。

## 分析（2026-10-14：读代码 + 临时用例复现；用例跑完删了，没进仓库）

### 不受影响的

- **判断新增**：只拿分享这边的列表和快照对照（`known`：分享里的相对路径 + sha1 / 夸克 fid，`follow/diff.ts`），不看网盘上的文件名。整理改名、挪走，不会重复转存，也不会漏集。
- **落点被整理挪走**（5633d12，2026-09-28 真机验过）：
  - 订阅的保存目录被腾空删掉：整理收尾把 `subPath` 改到作品目录（`rewriteFollowSubPaths`），撤销时改回。
  - 分享里那一层被腾空删掉：下一轮按原名建回来，整个交给整理，挪完删掉。

### 出问题的：新集整理时用不上上次的纠正

布景：假网盘 + TMDB 桩。《我和僵尸有个约会》在 TMDB 上有两季（33 / 43 集）。分享里两集，名字是 `我和僵尸有个约会.EP01.mkv` 这种、没写季。第一次手动整理把季改成 2 并执行。之后分享里来了第 3 集，追更检查，任务的自动整理是「把握大的直接执行」。

| 场景 | 新集落在 | 整理怎么认 | 结果 |
|---|---|---|---|
| A 分享里是片名目录，订阅的保存目录是任务根；勾了「记住这个识别」 | 重建的原名目录 | 按目录名重新识别，把握一般，季没带过来 | 规划成 S01E03，停在待确认 |
| A2 同 A，但分享里的目录名带年份 | 重建的原名目录 | 标题和年份都对上，把握大 | **直接执行成 S01E03** |
| B 分享里是散文件，订阅的保存目录就是那个目录；勾了记住 | 作品目录（`subPath` 跟过去了） | 上次确认过的识别结果，季 2 | S02E03，对 |
| B2 同 B，没勾记住 | 作品目录 | 目录名里的 tmdbid 标签，把握大，季没了 | **直接执行成 S01E03** |
| C 作品目录记着「季 = 2」，同一部剧第 1 季的 `S01E05` 落进作品目录（监控 / 别的追更） | 作品目录 | 上次确认过的识别结果，季覆盖压过文件名里的 S01 | **直接执行成 S02E05** |
| C' 同 C，手动整理整个作品目录 | — | 同上 | 第 1 季的文件都规划去 Season 02，撞上冲突 |
| D 作品目录记着「集偏移 = +12」，手动再整理一遍 | — | 同上 | 已经整理好的 `S02E13` 规划成 `S02E25` |

原因：

1. **纠正只存在「记住这个识别」里，而且挂在作品目录的路径上。** 整理收尾把记忆写在 `dstRoot`（`apply.ts` 的 `afterApply`），查的时候按单元根路径精确匹配（`preview.ts` 里的 `recallMatch`）。新集落回重建的原名目录（A）查不到；落进作品目录但没勾记住（B2）也没有。作品目录名里的 tmdbid 标签只带作品、不带季，还让把握变大、直接执行。
2. **记忆里的季 / 集偏移是整个单元强制套用**（`resolveEpisode` 最后一步，压过文件名里的季）。作品目录以后还会收别的季、别的来源的文件，记忆一跟到作品目录就会串（C / C'）；整理好的文件再整理一遍，偏移再加一次（D）。
3. **识别词里的 `s=` / `e=` 没生效。** `{[tmdbid=…;type=tv;s=2]}` 能解析出季（`rules.ts`，单测只验了解析），但识别和规划只用了 tmdbid。设置页的说明和示例都写着它。
4. **手动整理把范围直接选在「某剧 第二季」这种目录上**、里面的文件名带片名时，单元用文件名的解析，目录名里的季丢了，规划成第 1 季（`units.ts` 里 `useFiles` 那个分支）。自动整理按新增路径走时又认得出季 2，两边不一致。

## 推荐方案

季 / 集偏移这类纠正跟着**来源**走，不跟着作品目录走。追更就是一个来源：它知道新集来自分享里的哪个目录，就该记住这个目录上次是怎么整理的，新集带着这个结果交给整理。作品目录上的记忆只用来补空。

分四块，各自一个提交，按后面「实施顺序」做。

### 一、追更记住整理结果，新集带着交给整理（主体）

**记什么**：`share_follows.organized`（JSON 数组，迁移 0023）。一条对应分享里的一个目录：

```ts
interface ShareFollowOrganized {
  /** 分享里的目录（相对被盯目录，"" 是被盯目录本身）：只管直接放在这一层的文件 */
  dir: string;
  mediaType: "movie" | "tv";
  tmdbId: number;
  title: string;
  year: string;
  /** 整理时人定的季：新文件照样强制用 */
  season: number | null;
  /** 没人定季时，这批文件最后落到的季（一致才记）：新文件名、季目录、目录名都没给季时才用 */
  seasonFallback: number | null;
  /** 整理时的集偏移 */
  episodeOffset: number;
  /** 作品目录、这批视频现在所在的目录（相对任务 originPath）：之后在整理页动它们时，靠它认出是这条追更的 */
  workDir: string;
  filesDir: string;
  /** 最后一次真改了它的整理；撤销那次就退回 prev，没有 prev 就删 */
  runId: string;
  prev: Omit<ShareFollowOrganized, "prev"> | null;
  /** ms */
  at: number;
}
```

**什么时候记**：整理执行的收尾（`afterApply`，在改写 `subPath` 之前）。整理把这次挪过 / 改过名的视频交给追更：源路径、目标路径、所在单元的匹配 / 季 / 偏移 / `dstRoot`、从目标文件名或目标目录解析出的季。追更这边的处理放进 `follow/service.ts` 的新函数，和 `rewriteFollowSubPaths` 放在一起。

1. 源路径去掉订阅的 `subPath` 后在快照里：这是这条追更转存来的原样文件。按它在分享里的目录分组，记下或更新那一条。同一个目录的文件进了不同作品：删掉那条，不猜。
2. 这次挪了某条记录 `filesDir` 里的视频（在整理页对作品目录换匹配、改季、改模板后重整）：按那个单元更新这条记录。
   - 匹配和作品目录换成新的。
   - 人定了季就换季。
   - 集偏移累加：新偏移是在上次结果的基础上再偏的。
   - `filesDir` 跟到新位置。
3. 值没变就不动 `runId` / `prev`。追更每来一集就整理一次，不能把「最后一次真改了它的整理」刷掉。
4. 其余记录的 `workDir` / `filesDir` 按目录映射改写（和 `subPath` 一样）。

**撤销**（`afterRevert`）：`runId` 是这次撤销的整理时，有 `prev` 就退回 `prev`，没有就删；其余记录按反向映射改写。

**怎么用**：

1. 追更每组转存时，看组里的**文件**（不含目录）：父目录正好是某条记录的 `dir`，就给每个文件带一条提示，内容是落地后的路径、作品、季、补空季、偏移和追更名。
2. 提示一路传到整理：
   - `saveSelectionToTask` 加 `organizeHints`；
   - `files.landed` 事件带上 `hints`；
   - 自动整理攒着时按路径合并，遇到 409 重排时也带着；
   - `createRun({ hints })` 存进 `organize_runs.hints`（JSON，迁移 0023）；
   - 重新预览时一起带过去。
3. 预览时，一个单元里的视频全被提示覆盖、而且是同一条：
   - **识别**：排在识别词直指之后、记忆之前。用提示里的作品，把握大，理由写「沿用追更「X」上次的整理」。识别词直指了别的作品时照识别词，提示里的季 / 偏移不用，写一句说明。
   - **季 / 偏移**：提示里人定的季和偏移写进单元，和人在预览里改的一样，界面上看得到、能改。补空季放进规划状态，`resolveEpisode` 在文件名、季目录、目录名都没给季时才用。有提示就不再看记忆。
   - 只部分覆盖，或者几条提示不一样：不沿用，写一句原因。
   - 人在预览里换了匹配：补空季跟着清掉（那是上一部作品的）。
4. 界面和智能体：
   - 追更页每条订阅显示「整理沿用：片名 (年) · 第 N 季 · 集偏移」，可以「不再沿用」（`PUT /api/follow/:id { clearOrganized: true }`）。
   - 订阅换任务时自动清掉。
   - 智能体的 `follow_list` 带上摘要，`follow_update` 加 `clearOrganized`。

**不变的**：

- 任务的自动整理关着：新集照旧不整理。
- 「生成待确认清单」：照旧等人确认，只是作品和季已经带好。
- 分享里新出现的子目录（比如新一季的文件夹）：照常识别；整理过一次后也会记下来。
- 追更建在整理执行之后（智能体那边自动执行快的时候会这样）：第一集照常识别，整理过一次就记住了。
- 新集落在哪：不改，还是「重建原名目录」和「作品目录」两条路。

### 二、识别词里的 `s=` / `e=` 生效（小修）

- 命中目录名的（挂在单元上的直指）：`s` 当这个单元的强制季，人在预览里改的优先。
- 命中文件名的（挂在文件上的直指）：`s` / `e` 只管这一个文件。
- 单测补上规划结果，不只验解析。

### 三、范围根目录名里的季别丢（小修）

`units.ts`：单元用文件名的解析时，如果文件没写季、单元根不是任务根、目录名能当片名、目录名里有季，就用目录名里的季。补用例：范围选在「某剧 第二季」上时，`某剧.EP01.mkv` 规划成 S02E01；`tv`、`inbox` 这种范围照旧。

### 四、记忆的季 / 集偏移改成只补空（行为变化，要你点头）

「记住这个识别」记下的季 / 集偏移，以后只用在**文件名没写季**的文件上；季目录、目录名也没给季时才用记忆里的季。人在这次预览里改的照旧强制。

- 解决 C / C' / D：别的季、整理好的文件不再被压，再整理一遍也不会重复加偏移。
- 代价：分享者把第 2 季标成 `S01Exx`、你改成季 2 并记住的，以后从监控 / 云下载进来的同类文件不再被强制改季。追更来的有第一块的提示管；其它来源可以写识别词（第二块修好之后 `s=` 管用）。
- 实现：
  - 预览里记忆的季 / 偏移不再写进单元的 `seasonOverride` / `episodeOffset`，放进规划状态当补空值，和第一块的补空季走同一个口子。
  - 单元提示里写清楚补了什么。
  - 勾「记住」时，单元上没改季 / 偏移的，保留原来记着的值。
  - 识别记忆对话框的说明改一句。
- 不做这一块的话：第一块第 2 条（整理页改季、改偏移后跟着更新）分不清单元上的季 / 偏移是人改的还是记忆带出来的，记忆里的偏移会被累加进记录。得改成先查记忆，值相同就当没改。

## 实施记录

### 第二块：识别词 `s` / `e`（2026-10-14）

- `units.ts`：单元多一个 `dirDirect`，只在识别词命中目录名时有（命中文件名的还在各文件的 `direct` 上）。
- `plan.ts` 的 `resolveEpisode`：
  - 文件上的直指（`pin`）：直指的就是认出来的作品时，`s` / `e` 只管这个文件，压过季覆盖和集偏移。
  - 目录名上的直指：`s` 先当基准季（折算绝对集数按它），最后再强制；人在预览里改的季优先，特别篇照旧是第 0 季。
  - 直指的不是认出来的作品（人换了匹配）：都不算。
- 设置页的说明不用改；`rules.ts` 开头补了一句 s / e 管哪些文件。
- 用例：`plan.test.ts` 一条；变异核对（去掉文件直指、去掉目录直指的季）各自失败。

### 第三块：范围根目录名里的季（2026-10-14）

- `units.ts`：单元用文件名的解析（范围根、文件名带片名）时，文件没写季、目录名里有季，就用目录名里的季。
- 用例：`units.test.ts` 一条（范围选在「某剧 第二季」上是季 2，自动整理本来就是季 2，`inbox` 照旧没有季）；变异核对失败。

### 第四块：记忆的季 / 集偏移只补空（2026-10-14）

- `plan.ts`：新的 `EpisodeFill`（季、集偏移、来源）。`resolveEpisode` 多一个 `fill` 参数：
  - 季：文件自己什么季都没给（文件名、识别词、季目录、目录名都没有）才用；补的是第 1 季不算用上。
  - 集偏移：只给文件名没写季的文件（原样编号）；识别词钉死集数的不偏。
  - 用上了就在单元说明里写一句：「按记住的识别：N 个没写季的文件放第 2 季、集数 +12」。
- `preview.ts`：记忆的季 / 偏移不再写进单元的 `seasonOverride` / `episodeOffset`，`memoryFill` 放进规划状态的 `fills`（认出来的不是记着的那部作品就不用）；重规划照用，人换了匹配就清掉。
- `apply.ts`：勾「记住」时这次没改季 / 偏移，同一部作品原来记着的留着。
- 识别记忆对话框、智能体 `organize_adjust` 的 `remember` 说明各补一句。
- 用例：`run.itest.ts` 一条（手动整理整个作品目录零变更、第 1 季的 `S01E05` 进第 1 季、没写季的 `EP02` 补成 S02E14 并写说明、勾记住不丢原来的）；四处变异（记忆写回单元、偏移不限没写季的、不补季、记住时不保留）各自失败。

### 第一块：追更记住整理结果（2026-10-14）

和计划的出入：

- 记录多了 `titles`（这批文件原名里的片名）：新文件写了片名、又对不上的不沿用。同一个分享目录里混进别的剧时，不会被当成这部剧直接执行。
- 只记剧集：电影目录以后来的新文件多半是别的电影。
- 撤销能往回退几版（`prev` 是一条链，最多留 5 层），不是只退一层；目录改写连上一版们一起改。
- 同一轮里按快照认出的原样文件，不再算成「整理页动了别的记录的文件」（两条记录的视频目录碰巧重合时会串）。
- 撤销收尾时一个视频都没退回（撤销被取消、在网盘上失败），记录不动。
- 提示没放进 `OrganizeRun`（界面用不着），存在 `organize_runs.hints`，`getRunHints` 取。
- 整理预览里「被 N 条追更引用」还是只数订阅的保存目录，没把记录里的目录算进去。
- 时序：追更一轮好几组时，前一组交给整理的那次可能在这一轮写快照之前就执行完，按快照认不出这批文件、记录就漏了。追更服务在内存里记「这一轮已经转存、还没写进快照」的路径，记录时一起算，检查结束清掉。

**真机发现的问题（已修）**：撤销改季那次之后，记录退回了第 2 季，但「视频所在目录」还是 `Season 03`，文件其实已经回到 `Season 02`。

- 原因：改季那次执行完改写路径时，把这次整理自己的目录映射（`Season 02` → `Season 03`）也套到了上一版上，撤销时退回的就是被改写过的上一版。
- 修法：目录改写只改当前版。上一版不用跟着改，因为动过这批文件的整理得先撤销，才能撤销更早的那次。

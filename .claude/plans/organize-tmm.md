# 整理模块对照 tinyMediaManager 的重设计分析（2026-10-21）

> 状态：**分析 + 方案，未实施**。模板 / 预设那一块的方案已经写在 naming-freedom.md 末节「模板 / 预设交互重做」，这里不重复，只在第六节补一条修正（服务器 × 结构两个轴）。
> tMM 的做法对着官方文档核过（docs/movies/settings、tvshows/settings、moviepanel、tvshowpanel、filters、renamer、博客 renamer-preview / scrape-dont-overwrite）；标 ✓ 的是文档确认的，没标的是印象。

## 一、两者的根本差别

tMM 是**库管理器**：先把数据源目录扫成一张持久的作品表（电影 / 剧 → 季 → 集），每一行带状态（NFO / 图 / 字幕有没有、新入库、元数据齐不齐），人在表上筛选、多选，再对选中的做动作（刮削 / 编辑 / 改名）。改名只是其中一个动作，用的是已经刮好的元数据。关掉再开，表还在。

freeStrm 的整理是**作业执行器**：每次是一个 run —— 选任务 + 范围 → 列目录 → 识别 → 规划 → 预览清单 → 执行 → 可撤销。作品只在这一次 run 里存在；跨 run 留下来的只有「识别记忆」（按目录记 tmdbId / 季 / 偏移 / 标题）和 TMDB 缓存。页面主体是 run（待处理列表 / 历史），不是作品。

这决定了差距在哪：

- **看全貌**：tMM 一眼看出库里多少没刮、多少缺图。freeStrm 要先跑一次整个任务的预览才知道哪些没识别、哪些不规范，而且清单随 run 过期（留存清理会删、重启后老 run「单元结构没保存下来」）。
- **累积**：tMM 上改过的就留在那一行。freeStrm 的改动只在 run 里，勾了「记住」才落到记忆；改标题 / 季偏移 / 钉集 / 改判这些，重新预览就没了（界面上明说「没记住的手动改动不保留」）。
- **动作粒度**：tMM 对选中的作品做动作；freeStrm 以目录范围为单位发起。

freeStrm 比 tMM 强、别丢的：预览即 run（整条清单可勾、可改）；执行记账 + 撤销；失败分类、续跑、放弃；四个自动触发点；网盘限流、风控整轮停；本地 strm 镜像；Emby 刷新与回填；智能体接口。tMM 的改名预览只是 dry run + 执行 ✓，没有撤销；tMM 也没有锁定条目（作者明确不做，v4.2 用刮削时「不覆盖已有数据」代替 ✓）。

## 三、重设计：库视图当前门，run 退为执行记录

### 信息架构

「整理」页打开就是当前任务（= 库）的作品表，不再是一张「任务 / 范围 / 预览」表单：

```
整理   任务 [115 · /tv ▾]   [按片名或目录找…]   [筛选 ▾]            [识别新入库 12]  [整理要动的 40]  [历史]  [记忆]
──────────────────────────────────────────────────────────────────────────────────────────
全部 320 · 新入库 12 · 没识别 5 · 把握不大 7 · 要动 40 · 冲突 2 · 缺集 9 · 重复 1 · 已规范 250 · 不整理 3
──────────────────────────────────────────────────────────────────────────────────────────
☐ 海报  作品                      类型  识别          命名            集          更新     
☐ ▣    怒呛人生 (2023)            剧集  ✓ 把握大       ! 要动 8 项      10/10       昨天      [整理] [编辑] […]
☐ ▣    葬送的芙莉莲 (2023)        剧集  ✓ 记忆         ✓ 已规范         26/28 缺 2   3 天前    [找资源] […]
☐ ▢    Dune.Part.Two.2024.2160p…  —     ✗ 没识别       —               —           新        [换匹配] […]
☐ ▣    沙丘：第二部 (2024)        电影  ! 基本对       ⚠ 冲突 1         —           新        [整理] […]
```

- 一行一个「作品单元」= 现在的 OrganizeUnit（目录），不是文件。手机上是卡片。
- 「要处理的在前」的默认排序和现在一样；筛选条上的数字就是 tMM 筛选面板的那一排。
- 点行打开右侧**详情抽屉**（手机全屏）：概览（海报、简介、状态条、季集格子：有的实心、缺的空心、未播的灰）、文件（现在的 原来 → 整理后 表 + 行内改 S / E + 探测标签 + 冲突办法）、编辑（换匹配 / 候选 / 改标题 / 季偏移 / 记住 / 以后不整理）、记录（这个目录历次整理，点进 run）。
- 行上动作：整理这部（起一个 run，范围 = 它的目录）、编辑、找资源、以后不整理。多选后：整理选中 N 部 / 重新识别 / 只选把握大的。顶上：识别新入库 / 整理所有要动的。
- **run 视图原样保留**：执行进度、失败面板、撤销、日志都不动，入口变成顶部「进行中」横幅、「历史」、行上「上次整理」。侧栏角标、待处理列表、Telegram 都不变。

### 数据：organize_library 表（迁移 0028）

```
organize_library   task_id, root_path（相对任务目录，主键）,
                   raw_name, parsed_title, parsed_year,
                   match(json: OrganizeMatch 去掉 candidates), confidence, source(nfo|library|memory|rule|search|manual),
                   title_override, year_override, season_override, episode_offset, pins(json), renames(json), kinds(json),
                   naming(json: { keep, changing, conflicts, failed, plannedAt }),
                   episodes(json: { [season]: present[] }), missing(int),
                   new_since(int|null), skip(bool), note,
                   last_run_id, identified_at, updated_at
```

- **谁写它**：预览 run 的识别 + 规划结束时按单元 upsert（match / naming / episodes）；执行完把 naming 置成已规范、root_path 换成 dstRoot（和记忆的 repath 同一处）；撤销反过来；同步 / 监控发现任务下新目录时插一行 `new_since = now`、没识别（自动整理开着的照旧起 run）。留存清理删 run 不影响它。
- **人工改动落在这里**：换匹配 / 改标题 / 季偏移 / 钉集 / 改名 / 改判写进对应列；起新 run 时单元从这一行初始化（run 里再改也回写）。「没记住的手动改动不保留」这条就没了；`organize_matches` 退化成「记住」的勾（或者并进来：skip / source=manual 都是它的事，合表要迁数据，第一版先留两张）。
- **状态口径**：识别 = 没识别过 / 没识别 / 拿不准 / 基本对 / 把握大 / 记忆；命名 = 没规划过 / 已规范 / 要动 N / 冲突 N / 有失败；新入库 = new_since 非空（起过 run 就清）；缺集 = 每季 episodeCount 减去 present，未播的（季详情 air_date 在今天之后）不算。
- **和现有三个模型的关系**：本地 strm 树是网盘镜像（不动）；收藏夹是分享索引（不动）；海报墙从 strm 树认作品（以后可以改读这张表，识别更准）。

### 风险

- 大库第一次要跑一遍整个任务的预览才有这张表（和现在一样慢，TMDB 4 req/s）；之后都是增量。
- 单元边界变了（用户在网盘手动挪目录）时行会失效：同步 / 监控的 remove 事件删行、create 插行，和记忆的处理一致。
- 混合库里一个目录认成电影、下次认成剧：按 root_path 覆盖，不留两行。

## 四、分阶段

**阶段 0：快赢，不动数据模型（合计约 3 天，每条独立可发）**

1. 媒体服务器预设：设置页「整理」顶上 Emby / Jellyfin / Plex / Kodi 四个按钮，按下设 id 标签写法、两类模板的文件名细节（Plex 小写 s01e01、文件名带年份）、Specials 目录名、花絮目录名（Emby / Jellyfin `extras`、Plex `Behind The Scenes` 等、Kodi `extras`）；模板预设改成只管结构（第六节）。0.5 天。
2. 缺集：规划时把每季出现的集号收进单元（`episodes`），卡片 / 状态条显示「缺 E03 E07」、筛选「缺集」、「找资源」带上剧名和季；`getSeasonEpisodes` 的结果补 `air_date`，未播的不算缺。0.5–1 天。
3. 「以后不整理这个目录」：`organize_skips(account_name, path, note)` + 设置页清单（可手填 glob）+ 卡片按钮；`buildUnits` 跳过并在清单里列成「不整理 N 个目录」。0.5 天。
4. 「编辑作品」合并弹框（换匹配 / 候选 / 改标题 / 季偏移 / 记住 / 不整理 一个弹框分段）+ 文件表行内改 S / E（输入框直接填，失焦就重规划；钉集弹框留给键盘不方便的手机）。1 天。
5. 卡片上列前三个候选 chip，一点就换匹配。0.25 天。

**阶段 1：库视图 v1（3–4 天，迁移 0028）**

表 + run 回填 + 执行 / 撤销 repath + 列表页（筛选 / 排序 / 搜索 / 多选 → 整理选中 / 重新识别）+ 详情抽屉（概览 / 文件 / 编辑 / 记录）+ run 视图改成从横幅 / 历史进；人工改动落表、起 run 时初始化；记住筛选。智能体工具加 `organize_library_list`（查）和 `organize_library_edit`（改）两个，放 organize 组。

**阶段 2：新入库与增量识别（2 天）**

同步 / 监控落新目录插行标新；「识别新入库」只识别不规划；「整理要动的」按命名状态起 run；首页 / 侧栏角标加「N 部新入库没识别」。

**阶段 3：可选**

重复作品筛选；系列缺片（TMDB collection parts 对库里有的，缺的接找资源）；垃圾文件挪进「垃圾文件」目录（等用户定规则）；首次使用向导（选服务器 → 选结构 → 开不开分类）。

## 五、不借的和理由

- NFO / 图片 / 预告 / 字幕刮削、Trakt、导出、后处理：产品定位不同，Emby 刮得准且已有回填。
- 自动刮削阈值数字、JMTE 表达式、自定义列：freeStrm 的三档置信度和 token 模板更好懂；自定义列对手机没意义。
- 锁定条目：tMM 自己也不做；freeStrm 用「不整理的目录」+ 人工改动落表两件事覆盖。
- 嵌套数据源 / 多电影目录开关：任务就是数据源，混合库已有分流。

## 六、对模板方案的修正：服务器 × 结构两个轴

naming-freedom.md 末节的预设列表里「Plex 风格」和「按年份分目录」是两种性质的东西：前者是服务器决定的细节（id 标签写法、文件名要不要带年份、季集大小写），后者是目录结构。合在一个下拉里，用户选了 Plex 就没法再选按年份。改成：

- **服务器**（设置页顶上四个按钮，tMM 的 Media Center Presets）：决定 id 标签写法 + 文件名细节 + Specials / 花絮目录名；两类模板一起改；也是「首次使用向导」的第一问。
- **结构预设**（每类一个下拉，naming-freedom.md 的方案）：默认 / 按年份分目录 / 按系列归档（电影）/ 动画绝对集数（剧集）/ 只归目录保留原文件名；每个预设按当前服务器生成文件名细节。

这样预设定义是 `结构 × 服务器 → 模板` 的小函数，不是五条写死的字符串；选择器反推当前状态时两轴各自匹配。

### UI 审查与修整（2026-10-21，用户：「设置那里新增的有点错乱了，整理这边的你也看一下」）

对着桌面 1920 和 390px iframe 截图看了设置页「整理与命名」、任务弹框「命名模板」、整理页清单（假数据）和文件表。设置页的问题和改法：

- **媒体服务器那一行**：四个 outline 按钮里当前那个只是 secondary，分不出来；窄屏 Kodi 掉到第二行和状态文字挤在一起；一整句说明直接摊在下面。改成和换匹配弹框一样的分段控件（`inline-flex rounded-md border p-0.5`，选中 `bg-brand/15 text-brand`），标签用正常的 Label + ⓘ 装说明，状态文字放右边、窄屏自己落到下一行。
- **tab + 面板没有归属**：tab 条下面直接跟预设 / 三格 / 示例，和下面的 id 标签三列、开关网格平铺在一起。现在 tab 条和面板收进一个 `rounded-lg border` 里（tab 条 `border-b bg-muted/40`，内容 `p-4`），一眼看出这一块是「两类模板」。
- **「花絮目录名」孤零零一行**：标签 + 输入框 + 一长句同行，句子折到下一行就散了。改成标准字段块（Label / 输入框 w-56 / 说明一行），跟「自定义识别词」同一副长相。
- **预设标签**：面板里的「预设」是 text-xs 灰字，和其它字段标签不一致，改成正常 Label。
- **不整理的目录**：空态从一行裸文字改成虚线框（和整理页「已规范」折叠行一个语言）；表单三个小标签补 `font-medium`、块改 `flex flex-col gap-1`（约定①）。

整理页卡片、文件表的行内季集、编辑弹框和 390px 下都没发现错位（文件表窄屏横向滚动是原来就有的）；任务弹框的命名块跟着面板的标签改法一起变。typecheck / lint 干净，截图复核过桌面和窄屏。

**整理页文件表（同日，用户：「选中框是靠上的，文字是垂直居中的」）**：根因是一行里的东西高矮不一（勾选框 16px、徽标 22px、「…」按钮 24px 还带 mt-1、文字行 16px）又都 `align-top`，第一行各自对不上。改法：表格 `leading-5`，每列第一行放进 `flex h-5 items-center` 的行框（勾选框、徽标、行尾「…」），「…」从「动作」列挪到行尾单独一列，冲突的「怎么办」和行内季集各自 `mt-1` 挂在第一行下面，触发器自己不再带 mt。目录操作清单同样处理。假数据截图核过（含冲突行、已试 N 轮、探测到、不变）。
